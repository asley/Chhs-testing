### Key implementation decisions (deviations from original spec)

- **Settings storage**: All Drive settings (enabled flag, folder ID, service account JSON, impersonation email, workspace domain) are stored as a single JSON blob in one `gibbonSetting` row (`scope=Reports`, `name=googleDrive`). The original spec called for two separate rows. This is simpler and equally secure.
- **`googleDriveWebViewLink` column**: Not added. The web view URL is derived on-the-fly via `GoogleDriveService::getWebViewLink($fileId)` (a simple string format — no API call). Eliminates a DB column for trivial overhead.
- **`uploadFile()` return type**: Returns `?string` (Drive file ID) rather than `array`. Callers derive the web view link separately using `getWebViewLink()`.
- **Impersonation**: The service account uses domain-wide delegation to impersonate a real Workspace user email (not the service account email itself). This resolved `storageQuotaExceeded` errors that occurred when uploading to a personal Drive folder as the service account.
- **Permission model**: Files are shared via `type: domain` (read access to all users in the configured workspace domain) rather than `type: anyone`. Domain is derived from `workspaceDomain` setting or inferred from the impersonation email.
- **Missing-file marker**: Instead of leaving `googleDriveFileID = NULL` for entries whose local PDF is gone, a `missing_local:{entryID}` marker is written. This prevents the same missing file from being re-attempted on every sync run. Force Re-sync does not re-queue missing-marked entries.
- **No chunked AJAX progress**: The bulk sync tool runs as a single synchronous POST with a configurable batch limit (1–500, default 300). PHP `set_time_limit(600)` covers large batches. Real-time progress was deferred to a future release.
- **Exception handling**: Generic `\Exception` is caught and stored in `$lastError` rather than a typed `GoogleDriveSyncException`. No typed exception class exists yet.
- **No Gibbon activity log entries**: Upload events are written to PHP error log (`error_log()`) and the first error of each sync run is stored in the session for UI display. `gibbonLog` integration not yet implemented.

## Product overview

### Document title and version

Google Drive Report Sync — PRD v1.2

### Product summary

CHHS operates a customized fork of the Gibbon school management system. Student progress report PDFs are generated by Gibbon and stored locally on the server under `/uploads/reports/`. While this local storage works for server-based downloads, it creates operational friction: reports are not accessible outside the local network without a VPN, sharing a report with a parent or external stakeholder requires manual file transfer, and there is no cloud-redundancy copy of the archive.

This feature adds automatic mirroring of all report PDFs to a school-controlled Google Drive folder using a Google Workspace service account. It introduces a settings page for administrators to configure the integration, a bulk migration tool to back-fill existing archived reports, and UI enhancements across the report archive listing so that teachers and admins see a direct Google Drive link alongside the existing server download link. Local storage behavior is unchanged — Drive is additive, not a replacement.

## Goals

### Business goals

- Provide cloud redundancy for all student report PDFs without displacing the existing local archive.
- Enable staff to access and share individual reports directly from Google Drive, reducing manual file-handling workflows.
- Bring the full historical report archive into Google Drive through a one-time bulk migration with no data loss.
- Leverage the school's existing Google Workspace for Education license at no additional software cost.

### User goals

- Administrators want a simple settings screen to connect the Gibbon instance to Google Drive, and a reliable tool to migrate the existing archive in a single supervised run.
- Teachers want a clearly visible Drive link in the report archive listing so they can open or share a report without downloading it from the server first.
- IT staff want a service-account-based integration that requires no per-user OAuth consent and fits within the school's Google Workspace security policies.

### Non-goals

- This feature does not replace the local `/uploads/reports/` storage. Server files are never deleted or moved.
- This feature does not expose Drive links to students, parents, or any unauthenticated users.
- This feature does not implement two-way sync. Changes made directly in Google Drive are not reflected back to Gibbon.
- This feature does not cover report generation logic itself. It only handles the upload step after a report file exists on disk.
- This feature does not support multiple Drive folders or per-class/per-year folder structures in the initial release.
- This feature does not implement per-user Drive permissions. Access to the Drive folder is managed at the Google Workspace admin level.

## User experience

### Entry points

- **Admin — Settings**: Reports module sidebar > "Google Drive Settings" menu item
- **Admin — Bulk migration**: Reports module sidebar > "Google Drive Sync" menu item (accessible to anyone with archive manage access)
- **Teacher/Admin — Archive listing**: Reports > View Report Archive > per-row Drive link next to the existing download link

### Core experience

**Configuring the integration (admin)**
An administrator navigates to Reports > Google Drive Settings. They enable sync, enter their Google Drive folder ID, paste the service account JSON key, enter the Google Account Email (a real Workspace user for impersonation), and optionally enter the Workspace Domain. On save, the key is masked in future page loads. The settings page includes step-by-step setup instructions inline.

**Running the bulk migration (admin)**
After configuration, the admin navigates to Reports > Google Drive Sync. The page shows summary counts: unsynced final reports, total final reports, missing-marked entries, and unsynced drafts. The admin sets a batch size (default 300) and clicks "Sync to Google Drive." After the POST completes, the page reloads showing scanned/attempted/synced counts and any error from the most recent failed upload. Missing local files are auto-skipped and marked so they are not re-attempted.

**Viewing Drive links (teacher)**
A teacher opens the Report Archive listing. For each report entry that has been synced, a "Drive" link appears alongside the existing download link. Reports not yet synced show no Drive link. Entries with `missing_local:` markers also show no Drive link.

### Advanced features

- **Idempotent re-migration**: Admins can re-run the bulk migration tool at any time. Only un-synced records (not missing-marked) are processed.
- **Force re-sync**: The "Force Re-sync Final Reports: Yes" option re-queues all previously synced final reports for re-upload. Useful after files are manually deleted from Google Drive.
- **Missing-file marker**: Entries whose local PDF cannot be found on disk are written with a `missing_local:` marker to prevent infinite retry loops.

### UI/UX highlights

- The service account JSON field shows a masked placeholder after initial save.
- Drive links in the archive listing are plain text links labelled "Drive" — no icon dependency.
- All Drive-related UI elements degrade gracefully: if Drive is unconfigured or a file ID is missing/invalid, no link is shown.
- Sync page displays draft count separately with a clear note that drafts are intentionally excluded.

## Technical considerations

### Integration points

- **Google Drive API v3**: All Drive operations use the `google/apiclient` Composer package. `GoogleDriveService` wraps `Google\Service\Drive` with the full `drive` scope (required for domain-wide delegation with impersonation).
- **Service account authentication**: Credentials are loaded from the JSON blob stored in `gibbonSetting`. The client is initialised per-request via `Google\Client::setAuthConfig()` with the decoded JSON array. Domain-wide delegation impersonates a real Workspace user via `setSubject()`.
- **DI container**: `GoogleDriveService` is registered as a shared service and retrieved via `$container->get(GoogleDriveService::class)`.
- **Gibbon report generation hooks**: FR-16 (auto-sync) requires identifying the exact point in `modules/Reports/src/GenerateReportProcess.php` where `gibbonReportArchiveEntry` rows are written, then inserting a Drive upload call with graceful failure handling.

### Data storage and privacy

- The service account JSON key is stored in `gibbonSetting` as a JSON-encoded blob. It is never written to any log file, error output, or page HTML.
- `googleDriveFileID` is stored in `gibbonReportArchiveEntry`. It is an internal identifier; not personally identifiable.
- `missing_local:{entryID}` marker values stored in `googleDriveFileID` are internal markers and are filtered out before rendering Drive links.
- Drive files are shared at the domain level (`type: domain`, `role: reader`, `allowFileDiscovery: false`) — accessible only to users authenticated in the school's Google Workspace tenant.

### Scalability and performance

- The bulk sync tool uses a single POST with `set_time_limit(600)`. For archives larger than ~500 files, chunked AJAX batching should be considered in a future release.
- Google Drive API quota (1,000 requests/100 seconds/user) is not actively managed. If quota errors occur during large syncs, failed entries remain un-synced and will be retried on the next run.
- `googleDriveFileID` should be indexed if archive listing queries filter on Drive sync status at scale.

### Potential challenges

- **FR-16 hook location**: `GenerateReportProcess.php` must be read carefully before inserting the auto-sync call. The upload must happen after the local file is confirmed written to disk, not before.
- **644 missing-local entries**: These entries have local PDFs that no longer exist on the server. They cannot be synced until the PDFs are regenerated or restored. The `missing_local:` marker must be cleared before a re-sync can be attempted.
- **storageQuotaExceeded**: This was previously encountered when the service account attempted to upload to a personal Drive folder under its own quota. Resolved by impersonating a real Workspace user. If the impersonation user's Drive quota is reached, this error will recur.
- **Force re-sync safety**: Force re-sync clears all non-missing `googleDriveFileID` values. If Drive files are not actually deleted (user ran force re-sync accidentally), duplicate files will be created in Drive. A "verify before re-sync" check could prevent this.
- **Gibbon upgrade compatibility**: `gibbonReportArchiveEntry` and `ReportArchiveEntryGateway` modifications must be re-applied after any upstream Gibbon merge.
